Pendahuluan

Latar Belakang & Masalah Bisnis Restoran

Tantangan Restoran Konvensional
  • Kompleksitas 3 Pilar Operasional: Menyelaraskan katalog makanan/minuman, giliran kerja pegawai, dan aliran nota pesanan.
  • Rawan Human Error: Pencatatan manual rentan salah hitung nota, salah jenis layanan (dine-in vs delivery), dan jadwal shift bentrok.
  • Sistem Kaku & Monolitik: Kode linier tanpa modularitas sangat sulit diperluas saat ada menu baru atau pegawai baru.
  • Ketiadaan Proteksi Data: Data sensitif seperti harga dan total bayar mudah tertimpa tanpa validasi.
Solusi Melalui Paradigma OOP
  • Modularitas Kelas Mandiri: Entitas Menu, Pegawai, dan Pesanan dipisahkan dalam class terisolasi yang rapi.
  • Enkapsulasi Keamanan: Seluruh atribut private hanya dapat diakses melalui method getter & setter publik terverifikasi.
  • Inheritance & Reusability: Kelas turunan mewarisi atribut induk tanpa menulis ulang kode (DRY Principle).
  • Polymorphism Dinamis: Fleksibilitas pemanggilan method tampilkanData() sesuai bentuk nyata objek saat runtime.

5 Pilar OOP

Pilar 1 & 2: Class & Object serta Encapsulation

1. Class & Object
  • Konsep: Class sebagai cetak biru (blueprint); Object sebagai instansiasi nyata di memori heap.
  • Bukti Kode:
    daftarMenu.add(new MenuMakanan(id, nama, harga));
    daftarPegawai.add(new Chef(id, nama, shift));
    daftarPesanan.add(new PesananDineIn(id, nama, total));
  • Manfaat: Setiap pesanan dan pegawai memiliki identitas dan state tersendiri yang aman di memori.
2. Encapsulation
  • Konsep: Proteksi data dari akses sembarangan dengan modifier private dan akses lewat Getter/Setter.
  • Bukti Kode:
    private String idPesanan;
    private String namaPelanggan;
    private int totalHarga;

    public void setTotalHarga(int totalHarga) {
    this.totalHarga = totalHarga;
    }
  • Manfaat: Menjaga konsistensi data saat fitur 'Ubah Data' (Menu 5) dijalankan.
5 Pilar OOP

Pilar 3: Inheritance (Pewarisan Sifat Antar Kelas)

Pewarisan Atribut & Constructor via 'extends' dan 'super(...)'
  • Pewarisan Modul Menu: MenuMakanan, MenuMinuman, dan MenuDessert mewarisi atribut idMenu, namaMenu, dan harga dari parent MenuRestoran.
  • Pewarisan Modul Pegawai: Chef, Pelayan, dan Kasir mewarisi idPegawai, namaPegawai, dan shiftKerja dari Pegawai.
  • Pewarisan Modul Pesanan: PesananDineIn, PesananTakeAway, dan PesananDelivery mewarisi idPesanan, namaPelanggan, dan totalHarga dari Pesanan.
// Contoh pada Chef.java
public class Chef extends Pegawai {
    public Chef(String idPegawai, String namaPegawai, String shiftKerja) {
        super(idPegawai, namaPegawai, shiftKerja); // Memanggil constructor parent Pegawai
    }
}
5 Pilar OOP

Pilar 4: Polymorphism (Dynamic Method Dispatch)

Satu Perintah, Beragam Perilaku
  • Method Overriding (@Override): Setiap child class meng-override method tampilkanData() dan tampilkanAktivitas().
  • Iterasi Polimorfik pada Main:
    for (Pegawai p : daftarPegawai) {
        p.tampilkanData();
        p.tampilkanAktivitas();
    }
  • Dinamis saat Runtime: Saat objek adalah Chef, dicetak tugas memasak; saat Pelayan, dicetak tugas meja tamu; saat Kasir, dicetak tugas transaksi pembayaran.

Pilar 5: Abstraction & Interface Contract

Interface LayananRestoran
  • Definisi Kontrak Bersama:

    }
  • Standarisasi Sistem: Menjamin seluruh entitas restoran wajib menyajikan status aktivitas operasionalnya.

  • Proteksi Instansiasi: Mencegah pembuatan objek umum (misal new Pegawai() dilarang oleh compiler).

Refleksi Proyek

Kendala Teknis yang Dihadapi & Solusi

1. Buffer Scanner Skipped Line
  • Masalah: Saat pemanggilan input.nextInt() diikuti input.nextLine(), input teks berikutnya langsung terlewat otomatis.
  • Penyebab: nextInt() hanya mengambil integer dan meninggalkan karakter newline (\n) di buffer stream.
  • Solusi: Menambahkan baris pembersih input.nextLine(); tepat setelah setiap eksekusi nextInt().
2. Sinkronisasi Struktur Tim
  • Masalah: Pada fase awal, penamaan method antar 3 modul berbeda-beda sehingga error saat digabung ke Main.
  • Penyebab: Kurangnya standardisasi antarmuka kontrak sebelum penulisan kode dimulai.
  • Solusi: Menyepakati Interface LayananRestoran dan struktur parent abstract class terlebih dahulu sebelum membuat subclass.
